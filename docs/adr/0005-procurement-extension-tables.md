# 保留旧表，以扩展表承接采购配置和订单关联

现有部署要求保留所有已有表结构，因此商品采购配置和库存快照放入 `procurement_goods`，客户订单的采购快照、支付确认和采购卡密关联放入 `procurement_orders`，第三方采购执行记录放入 `procurements`，通过已有商品、订单和卡密的 ID 关联。

这会增加关联查询，并要求在开放新代码流量前创建扩展表；作为交换，历史商品和订单可继续使用原有本地发卡流程，无需改动 `goods`、`orders`、`carmis` 的字段或回填采购配置。建表 SQL 和迁移均跳过已经存在的采购表，不自动修补其结构；订单快照、支付与采购任务、卡密入库与订单关联分别在对应的本地事务中保持一致。
