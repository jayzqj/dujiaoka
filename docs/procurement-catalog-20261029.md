## 库存实现

- `IfakaClient` 允许请求 `/shared/commodity/items`；列表请求连接上限 2 秒、总上限 4 秒。密钥仍只在服务器端解密、签名，不发送到浏览器。
- 首页读取商品分类前，按已启用、已上架、自动发卡的商品配置刷新库存。无 race/SKU 的商品共用一次列表请求，递归读取分类中的商品，并按 code 写入采购扩展表。
- 请求结果复用 30 秒，Redis 锁防止并发访问重复调用。每分钟的 `procurement:stock` 也强制刷新列表库存。
- 有 race 或 SKU 的商品保持使用 `/stock` 获取选定规格库存，不将列表总量误当作某一规格的库存。
- 接口错误、缺失商品、无效或重复 code 的库存标为未知；明确的 0 保留为 0。旧商品映射的迟到响应不能覆盖新映射。快照超过 60 秒仍按既有规则视为未知。
- 采购及成本规则没有改变：付款后本地卡密优先，缺货时采购；零库存/未知库存是否允许购买继续遵循已确认的补货策略。
